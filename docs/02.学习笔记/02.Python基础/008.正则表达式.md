# Python 正则表达式到底该怎么写？从元字符到 re 模块一次讲清楚

正则表达式是个「又爱又恨」的存在——写的时候像天书，看别人的正则像考古，但它确实能把一大坨字符串处理代码压成一行。Python 的 `re` 模块把它封装得挺友好，但有几个坑特别容易踩，尤其是「贪婪」和「换行」这两件事。

适合经常做文本处理、日志分析、数据清洗，或者一直靠 `str` 方法硬拼、想系统掌握正则的人。读完你能想明白三件事：**正则的元字符和量词怎么组合、re 模块各函数怎么选、以及那些「怎么都匹配不对」的时刻到底错在哪**。

## 一、正则是什么：re 模块与元字符

### re.match 与 re.search

正则就是一套**描述「字符串模式」的语言**。`re` 模块最常用的两个入口是 `match` 和 `search`，它们都返回一个 `Match` 对象（匹配到）或 `None`（没匹配到）。

```python
import re

s = "abc123"
print(re.match(r"\d+", s))       # None  match 只从开头匹配，开头是字母，失败
print(re.search(r"\d+", s))      # <re.Match object; span=(3, 6), match='123'>
print(re.search(r"\d+", s).group())   # '123'  用 group() 取出匹配内容
```

**误区一：`re.match` 只从字符串开头匹配，不是「搜索任意位置」**。很多人以为 `match` 是「找有没有匹配」，结果写 `re.match(r"\d+", "abc123")` 拿到 `None` 就懵了。想搜任意位置，用 `re.search`。这是新手第一坑。

### 元字符速查

正则里这些字符有特殊含义，不是字面意思：

| 符号 | 含义 | 示例 |
|------|------|------|
| `.` | 任意字符（除换行） | `a.c` 匹配 `abc` |
| `^` | 开头 | `^a` 匹配开头的 a |
| `$` | 结尾 | `c$` 匹配结尾的 c |
| `*` | 前一个 0 次或多次 | `ab*c` 匹配 `ac`、`abc`、`abbbc` |
| `+` | 前一个 1 次或多次 | `ab+c` 不匹配 `ac` |
| `?` | 前一个 0 次或 1 次 | `ab?c` 匹配 `ac`、`abc` |
| `{m,n}` | 前一个 m 到 n 次 | `a{2,4}` 匹配 `aa` 到 `aaaa` |
| `[ ]` | 字符集 | `[abc]` 匹配 a/b/c 中一个 |
| `( )` | 分组 | 见第三节 |
| `\` | 转义 | `\.` 匹配字面点 |

```python
print(re.search(r"a.c", "abc").group())    # abc
print(re.search(r"^a", "abc").group())     # a
print(re.search(r"c$", "abc").group())     # c
print(re.search(r"ab*c", "ac").group())    # ac
print(re.search(r"ab+c", "ac"))            # None
print(re.search(r"ab?c", "ac").group())    # ac
print(re.search(r"a{2,4}", "aaaaa").group())  # aaaa
```

## 二、字符类与量词：贪婪与惰性

### 字符类与预定义字符

`[ ]` 是字符集，里面列出的字符「任取其一」；`[^ ]` 是取反。常用字符集有预定义简写：

| 符号 | 等价 | 含义 |
|------|------|------|
| `\d` | `[0-9]` | 数字 |
| `\w` | `[a-zA-Z0-9_]` | 字母数字下划线 |
| `\s` | `[ \t\n\r\f\v]` | 空白 |
| `\D` `\W` `\S` | 取反 | 非数字/非单词/非空白 |
| `\b` | — | 单词边界 |

```python
print(re.search(r"[aeiou]+", "queue").group())   # ueue  连续元音
print(re.search(r"[^0-9]+", "ab12cd").group())   # ab  非数字部分
print(re.search(r"\d+", "年龄18").group())        # 18
print(re.search(r"\w+", "var_1").group())         # var_1
print(repr(re.search(r"\s+", "a b").group()))     # ' '  空白
```

### 量词与贪婪

量词 `* + ? {m,n}` 默认是**贪婪**的——能多匹配就多匹配。在量词后加 `?` 变成**惰性（非贪婪）**——能少匹配就少匹配。

**误区二：贪婪量词匹配过多**。这是正则里最高频的坑：想匹配 HTML 标签，结果贪婪的 `.*` 把后面全吞了。

```python
s = "<b>加粗</b><i>斜体</i>"
print(re.search(r"<.*>", s).group())    # <b>加粗</b><i>斜体</i>  贪婪，一口气吃到最后一个 >
print(re.search(r"<.*?>", s).group())   # <b>  惰性，吃到第一个 > 就停
```

**注意点**：`.*?` 是「懒匹配」的标准写法，遇到「用 `.*` 匹配出来太长了」的情况，第一时间想到给量词加 `?`。但惰性也不是万能的，遇到复杂嵌套还是要靠更精确的模式，别一味 `.*?` 糊。

## 三、分组与捕获：group、命名分组、非捕获分组

### 捕获分组与 group()

`( )` 把匹配的一部分「捕获」起来，之后用 `group()` 按编号取出。`group(0)` 是**整个匹配**，`group(1)` 起是各分组。

```python
m = re.search(r"(\d{4})-(\d{2})-(\d{2})", "日期2024-08-01")
print(m.group(0))     # 2024-08-01  整个匹配
print(m.group(1))     # 2024  第一个分组
print(m.group(2))     # 08
print(m.groups())     # ('2024', '08', '01')  所有分组元组
```

### 命名分组与非捕获分组（简要）

- `(?P<name>...)`：给分组起名字，用 `group("name")` 或 `groupdict()` 取，比靠编号更可读。
- `(?:...)`：**只分组不捕获**，当你只想「打包」一部分做量词或 `|` 分支，但不需要取出它时用。

```python
m = re.search(r"(?P<year>\d{4})-(?P<month>\d{2})", "2024-08")
print(m.group("year"))    # 2024
print(m.groupdict())      # {'year': '2024', 'month': '08'}

m = re.search(r"(?:\d{4})-(\d{2})", "2024-08")
print(m.groups())         # ('08',)  非捕获分组不计入编号
```

**`findall` 与分组的关系（坑）**：`findall` 在**没有分组**时返回匹配字符串列表；一旦正则里有**捕获分组**，它返回的就是「分组元组」列表，而不是整个匹配。

```python
print(re.findall(r"\d+", "a1b22c333"))          # ['1', '22', '333']
print(re.findall(r"(\d{4})-(\d{2})", "2024-08, 2025-09"))
# [('2024', '08'), ('2025', '09')]   有分组，返回的是元组！
```

**注意点**：如果你用 `findall` 只想拿整个匹配、又必须用分组，那就把分组改成非捕获 `(?:...)`，或者改用 `finditer`。

## 四、re 模块的常用函数与 flags

### 六大函数对比

| 函数 | 返回 | 用途 |
|------|------|------|
| `match` | Match / None | 从**开头**匹配 |
| `search` | Match / None | 搜**任意位置**第一个 |
| `findall` | list | 所有不重叠匹配 |
| `finditer` | iterator | 所有匹配的 Match 迭代器（省内存、能拿 span） |
| `sub` | str | 替换 |
| `split` | list | 按正则分割 |

```python
print(re.findall(r"\d+", "a1b22c333"))   # ['1', '22', '333']

for m in re.finditer(r"\d+", "a1b22"):
    print(m.group(), m.span())           # 1 (1, 2) / 22 (3, 5)

print(re.sub(r"\d+", "#", "电话123，邮编456"))      # 电话#，邮编#
print(re.sub(r"(\d{4})-(\d{2})", r"\2/\1", "2024-08"))  # 08/2024  反向引用 \2 \1
print(re.split(r"[,\s]+", "a,b c  d"))   # ['a', 'b', 'c', 'd']
```

**注意点**：`sub` 的替换串里 `\1`、`\2` 反向引用分组内容（上面把「年-月」换成「月/年」）；但记得替换串要用 `r"..."` 原始字符串，否则 `\1` 会被当转义字符。

### re.compile 与缓存

`re.compile()` 把正则「预编译」成一个 pattern 对象。**CPython 细节①：`re` 模块内部有编译缓存**——同一个 pattern 字符串会被缓存复用，所以 `re.compile(r"\d+")` 调两次拿到的甚至是**同一个对象**：

```python
p1 = re.compile(r"\d+")
p2 = re.compile(r"\d+")
print(p1 is p2)   # True  同 pattern 被缓存复用
```

**注意点**：既然模块自己会缓存，**不必为了「性能」手动 `compile`**。`compile` 真正的价值是**可读性**——pattern 复用多次时，起个名字比每次贴一遍字符串清楚。

### flags 标志（简要）

| 标志 | 作用 |
|------|------|
| `re.IGNORECASE` / `re.I` | 忽略大小写 |
| `re.MULTILINE` / `re.M` | `^` `$` 匹配每行开头结尾 |
| `re.DOTALL` / `re.S` | `.` 也匹配换行 |
| `re.VERBOSE` / `re.X` | 允许写注释、拆多行 |

```python
print(re.findall(r"^line\d", "line1\nline2"))           # ['line1']
print(re.findall(r"^line\d", "line1\nline2", re.MULTILINE))  # ['line1', 'line2']
print(re.search(r".+", "ab\ncd", re.DOTALL).group())    # 'ab\ncd'
```

## 五、常见坑与正则哲学

### 转义与原始字符串 r""

正则里 `\d` 表示数字，但如果用普通字符串 `"\d"`，Python 会先把它当转义序列处理（`\d` 恰好不是合法转义，会变成 `\d` 两个字面字符，但 `\b` 就会变成退格符 `\x08`）。所以**正则一律写 `r"..."` 原始字符串**：

```python
print(re.search(r"\d+", "123").group())    # 123  推荐写法
print(re.search("\\d+", "123").group())    # 123  不用 r 就得写双反斜杠，难读
```

一个经典翻车：`re.search("\bword\b", ...)` —— `\b` 被 Python 转义成退格符，正则彻底错乱。写 `r"\bword\b"` 才对。

### `.` 不匹配换行，`^ $` 与 `\A \Z`

**误区三：`.` 不匹配换行符**。

```python
print(re.search(r".+", "ab\ncd").group())        # ab  (. 到换行就停了)
print(re.search(r".+", "ab\ncd", re.DOTALL).group())  # ab\ncd  加 DOTALL 才跨行
```

另外 `^ $` 默认匹配**整个字符串**的开头结尾，加了 `re.MULTILINE` 才匹配每一行；而 `\A \Z` 永远只匹配整个字符串的开头结尾，不受 MULTILINE 影响。想「严格锚定整个字符串」，用 `\A...\Z` 更保险。

### 灾难性回溯

**CPython 细节②：`re` 是回溯式引擎，错误写法会指数级爆炸**。回溯引擎遇到「尝试失败就退回重试」的模式时，嵌套量词会指数级地尝试所有可能性。最臭名昭著的是 `(a+)+` 这种「量词里套量词」：

```python
# 危险示例，别运行！随着 a 增多，匹配时间指数级爆炸
# re.match(r"(a+)+b", "a" * 20 + "c")
```

这类正则匹配失败时，引擎会穷举 `(a+)` 的每一种切分方式，20 个 `a` 就要试上百万次，30 个直接卡死。**避免方法**：别写嵌套量词；用 Python 3.11+ 的原子分组 `(?>a+)` 或占有量词 `a*+` 禁止回溯；或者干脆换更精确的模式。

### 什么时候用正则、什么时候别用

正则擅长**模式匹配和提取**（找邮箱、抓数字、拆日志），但不擅长**结构化解析**（HTML/XML/JSON）——用正则解析 HTML 是经典反模式，正确姿势是用 `html.parser`、`lxml`、`json` 这些专门工具。一个判断标准：**如果问题能用 `str` 方法（`split`/`startswith`/`find`）清楚解决，就别上正则**；只有当「模式」本身复杂多变时，正则才值回票价。


## 小结

回头看这条主线：**元字符 → 字符类与量词 → 分组捕获 → re 函数与 flags → 常见坑**。三句话收尾：

1. **`re.match` 只从开头、`re.search` 搜任意位置**；`.` 不匹配换行、`.*` 是贪婪的——这三个是「怎么都匹配不对」的头号原因。
2. **正则一律写 `r"..."`**，替换用反向引用也记得用 `r`。
3. **别用正则解析 HTML/JSON**，也永远别写嵌套量词——`(a+)+` 这类能卡死你的程序。

### 几个常见问题

**Q1：`match` 和 `search` 到底什么区别？**
`match` 从字符串**开头**匹配，开头不符合就返回 `None`；`search` 在**整个字符串里搜**第一个匹配。日常搜索用 `search`。

**Q2：为什么 `.*` 匹配出来的东西太长了？**
因为 `*` 是贪婪的，能多匹配就多匹配。在量词后加 `?` 变惰性：`.*?`。

**Q3：`findall` 返回的结果怎么和预期不一样？**
如果正则里有捕获分组 `()`，`findall` 返回的是**分组元组**列表，不是整个匹配。去掉分组或用 `(?:...)` 非捕获，或改用 `finditer`。

**Q4：为什么我的正则里 `\d` 不生效？**
大概率是没写原始字符串。`"\d"` 会被 Python 先转义，写 `r"\d"` 才对。

**Q5：能不能用正则解析 HTML？**
不能。正则不适合嵌套结构，用 `lxml`/`html.parser`。JSON/XML 同理，用专门的解析库。

### 本篇知识地图

| 知识点 | 一句话要点 | 关键结论 |
|--------|-----------|---------|
| match vs search | 开头 vs 任意位置 | 搜索用 search |
| 元字符 | . ^ $ * + ? {} [] () \ | 特殊含义，非字面 |
| 字符类 | [] 与 \d \w \s | 预定义简写 |
| 量词 | * + ? {m,n} | 默认贪婪 |
| 贪婪 vs 惰性 | 加 ? 变惰性 | `.*?` 是懒匹配标准写法 |
| 分组捕获 | () 与 group() | group(0) 是整体 |
| 命名/非捕获分组 | `(?P<name>)` / `(?:)` | 可读性 / 不占编号 |
| re 函数 | match/search/findall/finditer/sub/split | 各司其职 |
| compile 缓存 | 模块内部缓存 | 不必为性能手动 compile |
| flags | I/M/S/X | DOTALL 让 . 跨行 |
| 转义 | r"" | 正则一律写 r |
| 灾难性回溯 | 嵌套量词 | 别写 (a+)+ |
