# Python Web 开发到底该怎么写？从 HTTP 到框架一次讲清楚

Web 开发是 Python 最主流的战场之一。但要真正理解 Flask、FastAPI 这些框架，你得先知道它们底下是什么——HTTP 协议、WSGI 接口，以及「请求进来 → 框架处理 → 响应出去」这条链路。这篇就从 HTTP 讲起，一路讲到框架选型。

适合想写 Web 服务、API，或者用了框架却总觉得「背后有黑魔法」的人。读完你能想明白三件事：**HTTP 和 WSGI 是怎么回事、Flask/FastAPI/Django 各有什么定位、以及生产环境部署为什么不能图省事**。


## 一、HTTP 基础：请求、响应与状态码

### HTTP 是什么

HTTP 是**应用层协议**，跑在上一篇讲的 TCP 之上。浏览器/客户端发起一个「请求」，服务器返回一个「响应」，一问一答，无状态（每次请求互相独立）。

一个请求的核心结构是：**请求行（方法 + 路径 + 版本）→ 请求头 → 请求体**；响应对应的是：**状态行（状态码）→ 响应头 → 响应体**。

```text
GET /user/1 HTTP/1.1          ← 请求行：方法 GET，路径 /user/1
Host: example.com             ← 请求头
                              ← 空行
                              ← 请求体（GET 通常没有）

HTTP/1.1 200 OK               ← 状态行：状态码 200
Content-Type: application/json
                              ← 空行
{"id": 1, "name": "小明"}      ← 响应体
```

### 请求方法与状态码

**常用请求方法**：

| 方法 | 用途 |
|------|------|
| GET | 获取资源（不改变服务器状态） |
| POST | 创建资源 |
| PUT/PATCH | 更新资源 |
| DELETE | 删除资源 |

**常用状态码**：

| 状态码 | 含义 |
|--------|------|
| 2xx | 成功（200 OK） |
| 3xx | 重定向（301 永久、302 临时） |
| 4xx | 客户端错误（404 找不到、400 参数错） |
| 5xx | 服务器错误（500 内部错误） |

**注意点**：状态码是「给机器看的语义」。一个常见的坑是——**接口出错了却返回 200**，把错误信息塞在响应体里。正确做法是「出错就返回 4xx/5xx 状态码」，这样客户端、监控、重试机制才能正确识别。


## 二、WSGI：Python Web 的地基

### WSGI 是什么

**WSGI**（Web Server Gateway Interface）是 Python 定义的「**Web 服务器**和「**Web 应用/框架**」之间的标准接口。它规定了一个约定：服务器把一个叫 `environ` 的字典（请求信息）和 `start_response` 回调（发响应头）传给应用，应用返回响应体。

**CPython 细节①：WSGI 是「可插拔」的关键**。因为有了 WSGI 这个统一接口，任何实现了 WSGI 的服务器（gunicorn、uwsgi、waitress）都能跑任何实现了 WSGI 的框架（Flask、Django），两者可以自由组合。这是 Python Web 生态繁荣的地基。

一个**最小 WSGI 应用**（用标准库自带的 `wsgiref` 就能跑）：

```python
from wsgiref.simple_server import make_server

def application(environ, start_response):
    status = "200 OK"
    headers = [("Content-Type", "text/plain; charset=utf-8")]
    start_response(status, headers)
    return [b"Hello, WSGI!"]

# 启动服务器：make_server("127.0.0.1", 8000, application).serve_forever()
```

**注意点**：`environ` 里有 `REQUEST_METHOD`、`PATH_INFO`、`QUERY_STRING` 等请求信息；`start_response` 用来发状态码和响应头；返回的 `[b"..."]` 是响应体（必须是 bytes）。框架（Flask 等）本质上就是帮你把这些 `environ`/`start_response` 的脏活包起来。


## 三、Flask：轻量框架入门

Flask 是个「微框架」——核心极简，路由、请求、响应这些基础能力都有，剩下的（数据库、表单）靠插件。

### 路由与视图

```python
from flask import Flask, request

app = Flask(__name__)

@app.route("/")
def index():
    return "Hello, Flask!"

@app.route("/user/<name>")     # <name> 是路径参数
def user(name):
    return f"Hello, {name}"

@app.route("/query")           # 从 query string 取参数
def query():
    return f"q={request.args.get('q')}"
```

用 Flask 自带的测试客户端跑一下（不真起服务器）：

```python
client = app.test_client()
print(client.get("/").get_data(as_text=True))          # Hello, Flask!
print(client.get("/user/小明").get_data(as_text=True))  # Hello, 小明
print(client.get("/query?q=hi").get_data(as_text=True))  # q=hi
```

**注意点**：`@app.route("/user/<name>")` 里 `<name>` 是路径参数，自动传给视图函数；`request.args` 拿 query 参数、`request.json` 拿 JSON body、`request.form` 拿表单。

### 请求参数与响应

```python
@app.route("/api", methods=["POST"])
def api():
    data = request.get_json()          # 解析 JSON body
    return {"echo": data, "code": 0}   # 返回 dict 自动转 JSON
```

**误区一：不校验请求参数**。框架不会自动校验「传进来的数据合不合规」——`request.get_json()` 可能返回 `None`，`request.args.get("id")` 拿到的是字符串不是数字。写接口第一件事就是**校验参数**，别假设客户端一定按约定来。（FastAPI 用类型注解自动做这件事，见下一节。）


## 四、FastAPI 与 Django：现代与全栈

### FastAPI

FastAPI 是近几年最火的「现代 API 框架」，最大的卖点是**用类型注解自动做校验 + 自动生成文档**。

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def index():
    return {"message": "Hello, FastAPI!"}

@app.get("/items/{item_id}")
def get_item(item_id: int):        # 类型注解：item_id 必须是 int
    return {"item_id": item_id, "double": item_id * 2}
```

验证一下（FastAPI 会自动把 `item_id` 转成 int，还会校验类型）：

```python
from fastapi.testclient import TestClient

client = TestClient(app)
print(client.get("/").json())          # {'message': 'Hello, FastAPI!'}
print(client.get("/items/42").json())  # {'item_id': 42, 'double': 84}
```

**注意点**：FastAPI 原生支持 `async def`（异步视图）、自动生成 OpenAPI/Swagger 文档（访问 `/docs` 就能看到可交互的 API 文档）。跑起来用 `uvicorn app:app --reload`。

### Django

Django 是「全栈框架」，开箱自带 ORM、admin 后台、用户认证、表单。理念是「大而全、约定大于配置」，适合大型全栈项目。代价是更重、更「框架化」，学习曲线更陡。和 Flask/FastAPI 不是非此即彼，而是「你要不要它自带的那一大堆东西」。

## 五、数据库、部署与选型

### ORM

ORM（对象关系映射）让你用「操作 Python 对象」的方式操作数据库，不用手写 SQL。SQLAlchemy（配合 Flask/FastAPI）和 Django ORM 是两大主流。好处是防 SQL 注入、可读性好；代价是复杂查询不如手写 SQL 灵活。

### 部署：别用开发服务器

**误区二：把 Flask/FastAPI 自带的开发服务器直接上生产**。`app.run()`（Flask）和 `uvicorn` 的开发模式，目的是「调试方便」，**性能和安全性都不适合生产**。生产部署的正确姿势是：用专门的 **WSGI/ASGI 服务器**（gunicorn、uwsgi、waitress）来跑你的应用，前面再套 Nginx 处理静态文件、负载均衡、HTTPS。

```bash
# 生产用 gunicorn 跑 Flask 应用（app.py 里的 app）
gunicorn -w 4 -b 0.0.0.0:8000 app:app
```

**误区三：状态码语义搞混**。接口出错返回 200、重定向语义乱用，都会让客户端和监控误判。成功就 2xx，找不到就 404，参数错就 400，服务器崩了就 5xx，别含糊。

### 框架选型

**对比表**：

| 维度 | Flask | FastAPI | Django |
|------|-------|---------|--------|
| 定位 | 轻量微框架 | 现代异步 API | 全栈框架 |
| 类型注解校验 | ❌ 手动 | ✅ 自动 | 部分 |
| 异步支持 | 有限 | ✅ 原生 | 部分 |
| 自带功能 | 少（靠插件） | 少 | 多（ORM/admin/认证） |
| 适合场景 | 小项目、灵活 | API 服务、高并发 IO | 大型全栈、CMS |

**选型原则**：只写 API → FastAPI；小项目、想要灵活 → Flask；大型全栈、要 admin 和认证 → Django。**别一上来就学最重的框架**，先搞清楚「我要的是 API 还是网站」。


## 小结

回头看这条主线：**HTTP → WSGI → Flask/FastAPI/Django → 部署与选型**。三句话收尾：

1. **HTTP 是 TCP 之上的应用层协议**，理解请求/响应和状态码，是所有 Web 开发的地基。
2. **WSGI 让服务器和框架可插拔**，框架只是帮你把 `environ`/`start_response` 的脏活包起来。
3. **写 API 校验参数、出错返回正确状态码、生产别用 dev server**——这是三个最高频的坑。

### 几个常见问题

**Q1：WSGI 到底是干嘛的？**
它是「Web 服务器」和「Web 框架」之间的标准接口，让 gunicorn 等服务器能跑任何框架，两者可自由替换。

**Q2：Flask 和 FastAPI 怎么选？**
写 API、想要自动校验和文档、需要异步 → FastAPI；小项目、图灵活 → Flask。两者都不带数据库，要自己配。

**Q3：为什么接口出错还返回 200？**
这是常见坏习惯。出错应返回 4xx/5xx 状态码，客户端和监控才能正确识别，别把错误信息塞在 200 的响应体里。

**Q4：能不能用 Flask 自带的 `app.run()` 上生产？**
不能。它仅供开发调试，性能和安全性都不够。生产用 gunicorn/uwsgi 等 WSGI 服务器，前面再套 Nginx。

**Q5：Django 和 Flask/FastAPI 是什么关系？**
Django 是「全栈」框架，自带 ORM、admin、认证；Flask/FastAPI 是「微」框架，只有核心。选谁看你要不要 Django 自带的那一大堆功能。

### 本篇知识地图

| 知识点 | 一句话要点 | 关键结论 |
|--------|-----------|---------|
| HTTP | 应用层协议，跑在 TCP 上 | 请求/响应 + 状态码 |
| 请求方法 | GET/POST/PUT/DELETE | 语义对应增删改查 |
| 状态码 | 2xx/3xx/4xx/5xx | 出错别返回 200 |
| WSGI | 服务器与框架的标准接口 | 可插拔的地基 |
| Flask | 轻量微框架 | 路由/请求/响应，靠插件扩展 |
| FastAPI | 现代异步 API | 类型注解自动校验+文档 |
| Django | 全栈框架 | 自带 ORM/admin/认证 |
| ORM | 对象操作数据库 | 防注入，复杂查询略弱 |
| 部署 | gunicorn + Nginx | 别用 dev server 上生产 |
| 选型 | 看你要 API 还是网站 | API→FastAPI，全栈→Django |
