# 大规模并行仿真训练全景

强化学习运动控制与传统机器人控制的一个重要区别，在于控制策略通常需要通过大量与环境的交互来学习。对于人形机器人而言，这些交互不仅涉及关节运动，还涉及浮动基座动力学、足地接触、摩擦、碰撞以及跌倒后的状态恢复。如果只在单个机器人实例上采集数据，训练往往会受到采样效率的限制，大规模并行仿真通过同时运行大量环境，让机器人在不同状态下执行动作，并将产生的数据交给强化学习算法更新策略。

以常见的 legged_gym + Isaac Gym + rsl_rl 技术栈为例，理解训练系统需要回答三个问题：机器人如何在仿真中并行运行？每次交互产生的数据如何进入 PPO？增加并行环境后，训练效率为什么会变化？

## RL 运动控制训练架构

在经典的 legged_gym 项目中，训练并不是一个单独的强化学习算法完成的，而是由仿真器、环境封装、策略网络和训练器共同完成。
- `Isaac Gym` 提供机器人物理仿真能力，包括刚体运动、关节约束、碰撞检测和接触动力学。它还支持将物理状态组织为 GPU Tensor，减少大规模并行环境与强化学习代码之间的数据传输开销；
- `Legged Gym` 在仿真器之上实现具体的机器人任务。它负责创建机器人和地形、定义观测与动作、计算奖励、判断终止条件，以及在 episode 结束后重置环境；
- `RSL-RL` 负责强化学习算法的执行，包括 Actor-Critic 网络、PPO 更新、Rollout 数据存储、优势估计、训练日志和模型保存。

三者的关系可以概括为：`Isaac Gym` 负责模拟物理世界，`Legged Gym` 负责定义机器人在这个世界中如何完成任务，`RSL-RL` 则根据交互结果学习控制策略。


## 大规模并行仿真的原理

### 并行环境

传统的单环境训练每次只控制一个机器人，策略执行动作后，仿真器推进机器人状态，再返回新的观测和奖励，下一步交互通常需要等待前一步仿真完成。并行环境则同时维护多个机器人实例，每个环境具有自己的机器人状态、任务状态和随机参数，但可以使用同一个策略网络生成动作。例如，设置 `num_envs = 4096`，意味着训练环境中有 4096 个并行环境实例，每个控制步，策略可以批量处理这些环境的观测，并生成相应的动作。

需要注意，4096 个环境不等于 4096 个独立训练出来的策略，通常情况下，它们共享同一套 Actor 网络参数，但由于初始状态、地形、命令或随机化参数不同，会产生不同的交互轨迹，这种设计能够在同一轮采样中获得大量不同状态下的数据。
