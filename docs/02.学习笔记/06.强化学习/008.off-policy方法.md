# Off-policy算法

PPO 在机器人运动控制里几乎是默认选择。它稳定、易实现、和现代深度学习框架无缝兼容，训练出的策略可以直接部署到真机上。但它有一个明显的短板：**它是 on-policy 的，样本效率很低**。

PPO 每采样一批数据，更新几轮之后就必须扔掉，重新采样。因为在策略梯度的期望$\mathbb{E}_{\pi_{\theta}}[\cdot]$里，数据必须来自当前策略$\pi_{\theta}$。参数一更新，策略就变了，旧数据的分布和新策略对不上，再用就是错的。这意味着：采样一万步仿真数据，更新十轮，扔掉，再采样一万步，再更新十轮，再扔掉。在四足机器人训练里，这通常需要几千万甚至上亿步的仿真数据。在仿真里这还好，物理引擎可以加速；但如果要在真机上微调，这个样本效率就完全不可接受了，你不能让真机摔几百万次来学习。

有没有办法让同一批数据反复使用，甚至在策略更新很多次之后还能用？有，这就是 **off-policy** 算法的核心思想。

## Off-Policy 的核心：行为策略与目标策略分离

回顾一下，on-policy 算法的行为策略和目标策略是同一个。PPO 用当前策略 $\pi_{\theta}$采样，也用当前策略$\pi_{\theta}$来估计价值、计算梯度，策略一更新，旧数据就作废。

Off-Policy 算法把这两者拆开。
- **行为策略**（behavior policy）负责和环境交互、产生数据，它可以是一个带噪声的、过时的、甚至完全随机的策略。
- **目标策略**（target policy）是我们真正想优化的策略，它可以是确定性的、贪婪的、不断改进的。两者不是同一个东西，所以行为策略产生的数据，对于优化目标策略来说，永远有效。

但 off-policy 也有代价。行为策略和目标策略不一致，意味着你采样的数据分布和目标策略的分布不匹配。你需要**重要性采样**来修正这个偏差，或者用**确定性策略梯度**来绕开概率分布的问题。而且，off-policy 算法通常比 on-policy 更难训练，因为它们需要同时维护多个网络（策略网络、价值网络、目标网络），网络之间的交互容易不稳定。

## DDPG算法

### 从DQN说起

DQN 在离散动作空间里非常成功。它用神经网络拟合 $Q(s,a)$，然后用 $\epsilon$-greedy 选动作：以概率 $1-\epsilon$ 选 $\arg\max_a Q(s,a)$，以概率 $\epsilon$ 随机选一个动作。

但连续动作空间里，$\arg\max_a Q(s,a)$ 没法直接求。你不能枚举所有动作，也不能对每个动作都算一遍 Q 值。DDPG 的解决方案非常巧妙：**用一个神经网络来输出那个最优动作。**

这就是 **Actor-Critic** 架构的又一次胜利。Critic 是 $Q(s,a)$，负责评估动作价值；Actor 是 $\mu_\theta(s)$，负责输出确定性动作。Actor 的目标就是让 Critic 的打分尽可能高：

\[
\max_\theta \mathbb{E}_{s \sim \mathcal{D}}\left[Q_\phi(s, \mu_\theta(s))\right]
\]

Critic 的目标是让 Q 值逼近真实价值：

\[
\min_\phi \mathbb{E}_{(s,a,r,s') \sim \mathcal{D}}\left[\left(r + \gamma Q_{\phi^-}(s', \mu_{\theta^-}(s')) - Q_\phi(s,a)\right)^2\right]
\]

注意这里的两个关键细节。
- Critic 的更新目标里用的是**目标网络** $Q_{\phi^-}$ 和 $\mu_{\theta^-}$，而不是当前网络。这是从 DQN 继承来的稳定性技巧：用一套缓慢更新的目标网络来生成 TD 目标，避免网络在追逐自己的过程中震荡。
- Actor 是**确定性**的，它输出一个具体的动作 $\mu_\theta(s)$，而不是一个分布,这就是**确定性策略梯度**（Deterministic Policy Gradient，DPG）的核心。

### 探索

确定性策略有一个天然的问题：它没有随机性，怎么探索？

DDPG 的做法是在动作上加噪声。训练时，Actor 输出 $\mu_\theta(s)$，然后加上一个高斯噪声或 Ornstein-Uhlenbeck 噪声：

\[
a_t = \mu_\theta(s_t) + \mathcal{N}(0, \sigma^2)
\]

这个噪声就是探索的来源。噪声大小通常随训练衰减，训练初期大，机器人到处乱试；训练后期小，机器人精细利用。部署时，噪声设为 0，直接用 $\mu_\theta(s)$，动作平滑确定。

### 经验回放与目标网络

DDPG 是 off-policy 算法，所以它也可以使用经验回放。每次和环境交互得到的 $(s,a,r,s')$ 存进回放池，训练时随机采样一个 batch。由于目标策略不依赖于行为策略，这些数据可以反复使用，样本效率远高于 PPO。

DDPG的完整流程如下：

```python
class DDPG:
    def __init__(self, state_dim, action_dim):
        self.actor = DeterministicActor(state_dim, action_dim)
        self.critic = Critic(state_dim, action_dim)
        self.actor_target = copy.deepcopy(self.actor)
        self.critic_target = copy.deepcopy(self.critic)
        self.actor_optimizer = torch.optim.Adam(self.actor.parameters(), lr=1e-4)
        self.critic_optimizer = torch.optim.Adam(self.critic.parameters(), lr=1e-3)
        self.buffer = ReplayBuffer(1000000)
        self.gamma = 0.99
        self.tau = 0.005

    def select_action(self, state, noise=0.1):
        action = self.actor(state)
        action += noise * torch.randn_like(action)
        return action.clamp(-1, 1)

    def update(self, batch_size=256):
        states, actions, rewards, next_states, dones = self.buffer.sample(batch_size)

        # Critic 更新
        with torch.no_grad():
            next_actions = self.actor_target(next_states)
            next_q = self.critic_target(next_states, next_actions)
            target_q = rewards + self.gamma * next_q * (1 - dones)
        current_q = self.critic(states, actions)
        critic_loss = F.mse_loss(current_q, target_q)

        self.critic_optimizer.zero_grad()
        critic_loss.backward()
        self.critic_optimizer.step()

        # Actor 更新
        actor_loss = -self.critic(states, self.actor(states)).mean()

        self.actor_optimizer.zero_grad()
        actor_loss.backward()
        self.actor_optimizer.step()

        # 软更新目标网络
        for param, target_param in zip(self.actor.parameters(),
                                        self.actor_target.parameters()):
            target_param.data.copy_(self.tau * param.data +
                                    (1 - self.tau) * target_param.data)
        for param, target_param in zip(self.critic.parameters(),
                                        self.critic_target.parameters()):
            target_param.data.copy_(self.tau * param.data +
                                    (1 - self.tau) * target_param.data)
```

### DDPG 的问题

DDPG 在 2016 年发表时非常惊艳，但它很快暴露出两个严重问题。

**第一，Q 值高估。** 和 DQN 一样，DDPG 的 Critic 更新目标里用了 $\max$（通过 Actor 的确定性输出实现），这会导致 Q 值被系统性高估。高估的 Q 值会让 Actor 朝着错误的方向更新，训练不稳定甚至发散。

**第二，对超参数极其敏感。** DDPG 的学习率、噪声大小、软更新系数 $\tau$、网络结构，任何一个调不好，训练就会崩溃。同一个代码，换个随机种子，结果可能天差地别。这让 DDPG 在实际使用中非常痛苦。

这两个问题直接催生了 TD3。

## TD3算法

TD3，全称 Twin Delayed DDPG，是 2018 年提出的 DDPG 改进版。它用三个关键技巧解决了 DDPG 的不稳定问题。

### 双 Critic网络

DDPG 的 Q 值高估来自 $\max$ 操作。TD3 的做法是：**训练两个独立的 Critic 网络，取它们的最小值作为 Q 值估计。**

\[
y = r + \gamma \min_{i=1,2} Q_{\phi_i^-}(s', \mu_{\theta^-}(s'))
\]

为什么取最小值？因为两个 Critic 的估计误差是独立的。如果一个高估了，另一个可能没有；取最小值就抵消了高估的倾向。这和 Double DQN 的思想一脉相承，只不过 TD3 用的是两个完整的 Critic 网络，而不是一个网络的两个输出头。

```python
class TD3Critic:
    def __init__(self, state_dim, action_dim):
        self.Q1 = QNetwork(state_dim, action_dim)
        self.Q2 = QNetwork(state_dim, action_dim)  # 独立初始化

    def forward(self, s, a):
        return self.Q1(s, a), self.Q2(s, a)

    def target_min(self, s, a):
        return torch.min(self.Q1(s, a), self.Q2(s, a))
```

### 延迟更新

DDPG 同时更新 Actor 和 Critic。Critic 还没学好，Actor 就根据错误的 Critic 信号更新了，这会让训练很不稳定。TD3 的做法是：**Critic 每一步都更新，Actor 每隔几步才更新一次。** 通常每隔 2 步更新一次 Actor。这样 Critic 有更多时间把自己的估计变准，Actor 收到的信号也更可靠。

```python
for step in range(total_steps):
    # 每步都更新 critic
    update_critic()

    # 每 d=2 步才更新 actor + 目标网络
    if step_count % policy_delay == 0:
        update_actor()
        soft_update_targets()
```

### 目标策略平滑

DDPG 的 Critic 更新目标里，下一步动作是 Actor 目标网络直接输出的 $\mu_{\theta^-}(s')$。如果这个动作恰好是一个 Q 值被高估的“尖峰”，Critic 就会把这个错误放大。TD3 的做法是：**给目标动作加一点噪声，让 Q 值估计更平滑。**

\[
a' = \mu_{\theta^-}(s') + \text{clip}(\mathcal{N}(0, \sigma), -c, c)
\]

这个噪声被裁剪到 $[-c, c]$ 范围内，避免噪声太大。加噪声后，Critic 学到的 Q 函数在动作维度上更平滑，不会因为某个尖峰动作而崩溃。

TD3 的更新代码在 DDPG 基础上做三处修改：

```python
class TD3:
    def update(self, batch_size=256):
        states, actions, rewards, next_states, dones = \
            self.replay_buffer.sample(batch_size)

        # === Critic 更新（双 Q + 目标平滑） ===
        with torch.no_grad():
            next_actions = self.actor_target(next_states)
            # 目标策略平滑：给 target 动作加截断噪声
            noise = (torch.randn_like(next_actions) * 0.2).clamp(-0.5, 0.5)
            next_actions = (next_actions + noise).clamp(-self.action_max, self.action_max)
            # 双 Q 取 min
            target_q1, target_q2 = self.critic_target(next_states, next_actions)
            target_q = torch.min(target_q1, target_q2)
            target_q = rewards + self.gamma * (1 - dones) * target_q

        current_q1, current_q2 = self.critic(states, actions)
        critic_loss = F.mse_loss(current_q1, target_q) + F.mse_loss(current_q2, target_q)
        self.critic_optim.zero_grad(); critic_loss.backward()
        self.critic_optim.step()

        # === Actor 更新（延迟） ===
        if self.step_count % self.policy_delay == 0:
            # 注意：用 Q1 来更新 Actor 就够了
            actor_loss = -self.critic.Q1(states, self.actor(states)).mean()
            self.actor_optim.zero_grad(); actor_loss.backward()
            self.actor_optim.step()

            soft_update(self.actor_target, self.actor, self.tau)
            soft_update(self.critic_target, self.critic, self.tau)
```

TD3 在 MuJoCo 的连续控制任务上比 DDPG 稳定得多，最终性能也更好。它成为了 off-policy 连续控制的标准基线之一。但它仍然有一个问题：探索靠的是**外部加噪声**，噪声大小需要手工调；而且它学的是确定性策略，在某些需要随机策略的任务上表现不好。这就引出了 SAC。

## SAC算法

SAC，全称 Soft Actor-Critic，是 2018 年提出的 off-policy 算法。它在 TD3 的基础上引入了**最大熵框架**，让探索内生于策略本身，而不是靠外部加噪声。

### 最大熵目标

标准强化学习的目标是最大化期望累积回报：

\[
J(\theta) = \mathbb{E}\left[\sum_t \gamma^t r_t\right]
\]

SAC 在这个目标里加了一项**熵**：

\[
J(\theta) = \mathbb{E}\left[\sum_t \gamma^t \left(r_t + \alpha \mathcal{H}(\pi_\theta(\cdot|s_t))\right)\right]
\]

其中 $\mathcal{H}(\pi_\theta(\cdot|s_t)) = -\mathbb{E}_{a \sim \pi_\theta}[\log \pi_\theta(a|s_t)]$ 是策略的熵，$\alpha$ 是温度系数，控制“好奇心”的权重。

这个目标的意思是：**你既要拿高分，也要保持随机。** 熵越大，策略越随机，探索越充分。SAC 不是让策略自由地选择确定性，而是告诉它：你必须在保持一定混乱的前提下，尽可能拿高分。

这解决了 TD3 的一个根本问题。TD3 的探索靠外部噪声，噪声大小需要手工调；SAC 的探索是策略自身学出来的，标准差网络会自动调整。训练初期策略熵大，探索充分；训练后期熵收缩，利用为主。而且，最大熵目标让 SAC 在面对多模态奖励景观时更有优势——它不会过早坍缩到某一个确定性动作上，而是保留多个可能的好动作。

### 随机策略与重参数化

SAC 的 Actor 是一个随机策略，输出高斯分布的均值和标准差。但它不能直接从高斯分布采样，因为采样操作不可导，梯度传不回去。SAC 用**重参数化技巧**解决这个问题：

\[
a_t = \tanh\left(\mu_\theta(s_t) + \sigma_\theta(s_t) \odot \epsilon\right), \quad \epsilon \sim \mathcal{N}(0, I)
\]

把随机性从采样操作里“抽出来”，变成外部噪声 $\epsilon$，这样梯度就可以通过 $\mu_\theta$ 和 $\sigma_\theta$ 传回去了。$\tanh$ 把动作压缩到 $[-1, 1]$ 范围内。

### 双 Critic 与温度自适应

SAC 也用了双 Critic 取最小值来抑制高估，和 TD3 一样。但它的独特之处在于**温度系数 $\alpha$ 的自动调整**。SAC 设定一个目标熵 $\bar{\mathcal{H}}$（通常取动作维度的负数，比如 $-6$ 对于 6 维动作），然后自动调整 $\alpha$，让策略的实际熵接近目标熵。如果实际熵低于目标，增大 $\alpha$ 逼策略多探索；如果高于目标，减小 $\alpha$ 让策略多利用。这个闭环让 SAC 不需要手工调 $\alpha$，自适应地平衡探索和利用。

SAC 的完整更新包含三个损失：

```python
# Critic 损失（双 Critic）
with torch.no_grad():
    next_actions, next_log_probs = self.actor.sample(next_states)
    next_q1 = self.critic1_target(next_states, next_actions)
    next_q2 = self.critic2_target(next_states, next_actions)
    next_q = torch.min(next_q1, next_q2) - self.alpha * next_log_probs
    target_q = rewards + self.gamma * next_q * (1 - dones)

critic1_loss = F.mse_loss(self.critic1(states, actions), target_q)
critic2_loss = F.mse_loss(self.critic2(states, actions), target_q)

# Actor 损失（最大化 Q 值 + 熵）
new_actions, log_probs = self.actor.sample(states)
q1 = self.critic1(states, new_actions)
q2 = self.critic2(states, new_actions)
actor_loss = (self.alpha * log_probs - torch.min(q1, q2)).mean()

# 温度损失
alpha_loss = -(self.log_alpha * (log_probs + self.target_entropy).detach()).mean()
```

### SAC 的表现

SAC 在 MuJoCo 的连续控制任务上，样本效率远超 PPO 和 TD3，最终性能也相当甚至更好。在机器人运动控制里，SAC 特别适合那些需要精细操作、奖励信号复杂、或者需要快速适应新环境的任务。它的最大熵目标让策略保持多样性，在域随机化和 Sim-to-Real 中表现突出。

但 SAC 也有代价。它比 PPO 更难实现，网络更多（两个 Critic、一个 Actor、三个目标网络），超参数更多，训练时间更长。而且，SAC 是 off-policy 的，它依赖经验回放池的质量。如果回放池里的数据太旧、太偏，训练也会出问题。

## 三者对比与选择

| 维度 | DDPG | TD3 | SAC |
|:---|:---|:---|:---|
| 策略类型 | 确定性 | 确定性 | 随机 |
| 探索方式 | 外部加噪声 | 外部加噪声 | 策略自带熵 |
| Q 值高估 | 严重 | 双 Critic 抑制 | 双 Critic 抑制 |
| Actor 更新 | 同步 | 延迟 | 同步 |
| 温度系数 | 无 | 无 | 自适应 |
| 样本效率 | 中 | 高 | 最高 |
| 训练稳定性 | 差 | 好 | 好 |
| 实现复杂度 | 中 | 中 | 高 |
| 适用场景 | 简单连续控制 | 通用连续控制 | 复杂精细控制 |

**选哪个？**

如果你刚开始做连续控制，从 **TD3** 开始。它比 DDPG 稳定，比 SAC 简单，在大多数任务上表现都很好。

如果你追求最高样本效率，或者任务需要策略保持随机性、需要处理多模态奖励，选 **SAC**。它在机器人控制里越来越流行，尤其是需要精细操作和快速适应的场景。

**DDPG 现在基本不用了**，它更多是一个历史里程碑。理解了 DDPG，你就理解了 TD3 和 SAC 为什么要那样设计——它们都是在修补 DDPG 的缺陷。
