# Agent记忆系统

你是否经历过这样令人抓狂的时刻？你花了一个小时，耐心地教会你的AI编程助手你偏好的代码风格：变量命名要用下划线，注释要写在函数内部，测试框架必须用`pytest`。它点头称是，完美地完成了当前的任务。你心满意足，觉得终于有了个得力的帮手。然而，第二天，当你打开一个新的对话窗口，让它继续完成另一个模块时，它却像完全失忆了一样，用回了它默认的驼峰命名法，注释也写得敷衍了事。你所有的调教都付之东流，一切又要从头开始。这个问题的根源，就**在于目前的大语言模型核心是一个无状态的函数**。每一次与你的交互，对它来说都是一场全新的、与过往无关的初次见面，它当前所能依赖的，仅仅是上下文窗口，也就是当前这一轮对话中，你刚刚告诉它的有限信息。

这正是我们今天要解决的问题：为AI Agent构建一个持久的记忆系统。

## 记忆系统：让智能体拥有记忆

### 上下文窗口

在深入探讨Agent记忆系统的实现之前，我们有必要先厘清一个广泛存在的认知误区**上下文窗口并非记忆系统**，这是两个在概念和功能上截然不同的机制，却在日常讨论中经常被混为一谈。

上下文窗口本质上是大语言模型在单次推理过程中能够接收并处理的输入 Token 数量上限。它是模型架构层面的一个硬性约束参数，无论其具体数值是常见的128K、200K，还是某些模型宣称的更大规模，该窗口都严格界定了模型在生成当前输出时所能够感知的全部信息范围。在实际运行中，当前轮次的对话历史、用户的最新提问、预设的系统指令、工具调用的返回结果，乃至通过 RAG 方式获取的外部知识，都必须被拼接到这个窗口之内，模型方才具备基于这些信息进行推理的前提条件。从这个意义上说，上下文窗口承担的是工作空间的角色，它存放的是模型在当前时刻完成推理任务所必需的全部即时信息。上下文窗口在工程实践中呈现出三个核心特性，这些特性从根本上决定了它无法承担记忆的职能：

- **容量有限性**：无论窗口规格是4K还是200K，它始终存在一个明确且不可逾越的容量上限。当累积的对话信息总量超出该上限时，较早时间步的信息将被强制截断或丢弃，模型对此类内容将完全丧失感知能力，这在长周期对话场景中构成了根本性的信息丢失风险。
- **生命周期临时性**：上下文窗口的生命周期严格绑定于当前的会话进程。一旦会话终止、窗口被关闭，其中承载的全部信息包括完整的对话历史、中间推理步骤及工具调用结果等将被永久性地销毁，不受任何形式的持久化存储机制保护；
- **内容一次性**：窗口中的信息仅在当前这一次推理过程中生效。模型完成输出生成后，这些信息的使命即告终结。若需在后续的推理步骤中让模型继续记住其中某些内容，唯一的途径就是将这些内容重新拼入新一轮的上下文窗口，这是一种低效且成本高昂的重复注入操作。

### 记忆的类型

Agent记忆系统的设计，在理念上高度参照了人类认知科学中的记忆分层模型。人类的记忆并非一个简单的信息容器，而是一个结构精密的层级化认知系统，能够依据信息的重要性、时间维度及上下文关联对其进行分类、整理与优先级调度。下图展示了人类记忆的典型分层结构：

![](https://picupload-1330431167.cos.ap-guangzhou.myqcloud.com/images/20260716183544234.png)

根据认知心理学的研究，人类记忆可以分为以下几个层次：

- **感觉记忆**（Sensory Memory）：持续时间极短（0.5-3秒），信息容量巨大，负责瞬时保存感官器官所接收到的全部原始刺激信号，是信息进入认知系统的第一道入口；
- **工作记忆**（Working Memory）：持续时间为15至30秒，信息容量被限制在$7 \pm 2$个信息组块左右，负责承载当前认知任务所涉及的信息处理与操作，是意识活动的核心工作区;
- **长期记忆**（Long-term Memory）：持续时间可从数小时延续至终生，信息容量在理论上近乎无限。其内部可进一步细分为两大类别:
  - **程序性记忆**：负责存储各类技能与习惯性行为模式，如骑自行车、打字等自动化操作，通常难以用语言显式描述；
  - **陈述性记忆**：负责存储可以用语言明确表达的知识，并可进一步划分为：
    - **语义记忆**：存储关于客观世界的一般性知识与概念，如“巴黎是法国的首都”;
    - **情景记忆**：存储与个人经历相关的具体事件与情境，如“昨天下午三点的项目评审会议中讨论了预算调整方案”。

这一分层认知架构为Agent记忆系统的工程设计提供了重要的理论参照，后续章节将详细讨论如何在实践中映射并实现这些不同层级的记忆功能。

### 记忆系统的价值

人类智能之所以具备强大的适应性与创造力，一个关键因素在于我们能够**记住过去的经历，从中提炼规律与经验，并将这些经验灵活地应用于处理新的情境**。这一能力使人类得以在复杂多变的环境中持续学习和成长。

对于基于大语言模型的智能体而言，**其核心模型本质上是无状态的**,这意味着，每一次用户请求对模型来说都是一次独立的、与前序交互无关的计算过程。模型自身不具备自动留存或追溯过往对话内容的能力。这一根本性的架构特征带来了以下三个维度的系统性问题：

- **上下文断层**：在多轮次的长时间对话中，早期轮次所包含的重要信息可能因超出上下文窗口容量而被系统性地截断和丢失，导致Agent在对话后期无法完整理解用户意图，影响任务执行的连贯性与准确性。
- **个性化缺失**：Agent无法在跨会话的交互中记住用户的偏好设置、使用习惯或特定业务需求。这意味着即使用户长期使用同一个Agent，每次交互仍需重复告知基本背景信息，用户体验始终停留在初次见面的水平。
- **经验学习能力受限**：由于不具备跨任务的记忆机制，Agent无法从过往的成功经验或失败教训中进行总结与自我改进。每一次任务执行都独立于其他任务，Agent的能力无法随着使用次数的增加而逐步进化。

## 记忆的生命周期

对于 Agent 而言，记忆并不是简单地保存历史对话，而是贯穿整个智能体运行过程的核心能力。从用户输入开始，到知识的长期积累，再到后续任务中的调用，记忆经历了一个完整的生命周期。一个完善的 Agent 记忆系统通常包含五个阶段：**记忆编码、记忆存储、记忆检索、记忆注入和记忆更新**。这五个环节构成了 Agent 从经历到成长的完整闭环。

### 记忆编码

记忆编码是记忆生命周期的起点，其目标是将用户输入、环境状态以及 Agent 执行过程中的信息转换为适合**长期保存的结构化表示**。

现实中的用户输入往往包含大量无关信息，例如寒暄、重复表达、口语化描述等。如果直接全部保存，不仅会增加存储成本，还会降低后续检索效率。因此，编码阶段首先需要对原始信息进行分析和提炼，只保留真正具有长期价值的内容。通常，编码过程包括以下几个步骤：
- **信息提取**：识别用户偏好、身份信息、任务目标、约束条件等关键内容；
- **摘要压缩**：利用 LLM 将长文本压缩为简洁的摘要，减少冗余信息；
- **结构化表示**：将信息组织成统一的数据结构，例如 JSON、知识图谱或键值对形式。
- **向量化表示**：将文本编码为高维向量，为后续语义检索提供支持。

### 记忆存储

经过编码后的记忆需要保存到存储系统中。根据记忆持续时间和用途的不同，Agent 通常采用分层存储策略，而不是将所有信息放在同一个数据库中。不同类型的记忆通常对应不同的存储介质，常见的存储介质及对应存储的记忆有：
- **工作记忆**：工作记忆只保存当前 Agent 正在处理的信息，一般不会长期落盘，通常只存放在内存或者Redis数据库中；
- **情景记忆**：情景记忆记录 Agent 经历过的事件，这种记忆通常有两种保存方式：
  - 向量数据库：保存 Embedding，用于语义检索历史事件；
  - 文本数据库：保存原始文本，用于生成式对话，例如PDF、图片、日志等；
- **语义记忆**：语义记忆保存稳定的事实和知识，这种记忆通常有多种保存方式：
  - 关系数据库保存结构化事实；
  - 图数据库保存知识之间的关系；
  - 向量数据库保存知识的 Embedding，用于语义搜索；
- **程序记忆**：程序记忆保存 Agent 的技能和习惯，这种记忆通常以代码的形式保存，用于自动化操作，很多 Agent 以Prompt、Workflow、Skill Library等形式实现。

### 记忆检索

存储的记忆只有在需要的时候能够被准确找到，才真正具有价值,因此，检索是整个记忆系统最关键的环节之一。当用户提出新的问题时，Agent 会根据当前任务生成一个查询，然后从多个记忆源中寻找最相关的信息。

#### 检索触发机制

一个有记忆的 Agent，并不会在每次对话都去翻遍自己的记忆仓库，真正聪明的系统，知道什么时候该想起，触发检索的时机，其实构成了 Agent 的意识边界。常见的检索触发机制包括：
1. **上下文窗口不够**：当对话历史变长、任务链变复杂时，旧的信息被挤出窗口，模型开始遗忘，于是我们让 Agent 在这种情况下主动去检索，在工程上，这通常由一个简单的规则触发，当上下文长度接近阈值时，调用检索模块，把最相关的历史片段重新召回。
2. **事件触发**：有些记忆并不是因为遗忘才被召回，而是因为情境再次出现，比如，当一个任务执行失败、某个工具调用报错，Agent 会去搜索之前的失败记录，又或者，当用户在不同会话中再次提到某个主题，Agent 会识别关键词，自动检索该主题下的历史交互。

#### 检索策略

现代 Agent 记忆系统的核心检索策略不是互斥的，而是可以组合使用，共同提高记忆检索的准确率和召回率。常见的检索策略包括：
- **语义相似检索**：语义相似检索是目前 Agent 中最常见的记忆检索方式，其核心思想是不依赖关键词是否一致，而是根据文本语义的相似程度寻找最相关的记忆，系统利用 Embedding 模型将当前用户问题编码成一个高维向量。随后，向量数据库计算该向量与所有历史记忆向量之间的相似度，常用指标包括:
  - 余弦相似度
  - 内积
  - 欧氏距离
- **混合检索**：混合检索结合了多种检索策略，通过综合不同方法的结果来提高检索的准确性和完整性。例如，可以先进行语义相似检索，再结合关键词匹配检索，或者将向量检索与结构化数据检索相结合；
- **图式检索**：图式检索并不是根据文本相似度进行搜索，而是利用知识图谱中的实体关系进行推理，它将记忆组织为事件或知识图谱，更适合任务型 Agent；
- **元数据过滤**：元数据过滤是指在检索过程中，根据记忆的元数据（如时间戳、来源、标签等）进行筛选，以排除不相关或不合法的记忆；
- **重排**：重排是指在检索过程中，根据用户的意图和当前的任务目标，对检索结果进行重新排序，以提高匹配度和相关性，具体实现是使用一个额外大模型重新打分前 K 条结果；
