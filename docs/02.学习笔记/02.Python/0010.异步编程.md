# Python 异步编程

## 任务类型

在并发编程中，我们经常会听到 CPU 密集型和 I/O 密集型任务。但在实际项目中，任务的资源消耗模式往往更加复杂。

- **CPU密集型任务**（CPU-bound）是指需要进行大量计算、主要消耗CPU处理能力的任务；
- **IO密集型任务**（I/O-bound）是指大部分时间在等待输入输出（如文件读写、网络请求）完成的任务

|     特性      | CPU密集型任务                            | IO密集型任务                             |
| :-----------: | ---------------------------------------- | ---------------------------------------- |
| **核心瓶颈**  | 处理器算力（受限于CPU频率与核心数）      | 数据传输速度（受限于硬盘、网络带宽）     |
| **CPU利用率** | 极高（任务一直在干活）                   | 较低（大部分时间在等待数据返回）         |
| **常见场景**  | 科学计算、图像处理、视频编解码、加密解密 | Web服务器、数据库读写、文件传输、API调用 |

## 同步与异步

 IO在计算机中指Input/Output，也就是输入和输出。由于程序和运行时数据是在内存中驻留，由CPU这个超快的计算核心来执行，涉及到数据交换的地方，通常是磁盘、网络等，就需要IO接口。

由于CPU和内存的速度远远高于外设的速度，所以，在IO编程中，就存在速度严重不匹配的问题。例如，将 100MB 的数据写入磁盘时，CPU 生成和准备这些数据可能只需要 0.01 秒，而磁盘完成实际写入却可能需要 10 秒。如果处理不当，CPU 的大量计算能力将被白白浪费在等待上。

- 同步IO：CPU 发起写入请求后，会一直等待磁盘完成数据写入，然后才继续执行后续代码。在这段等待期间，程序处于阻塞状态，无法处理其他任务；
- 异步IO：CPU 发起写入请求后，不再等待结果，而是立即返回并继续执行其他任务。磁盘在后台完成数据写入后，再通过事件通知、回调函数或其他机制告知程序处理结果。

因此，同步 I/O 的特点是**发起操作后必须等待结果**，而异步 I/O 的特点是**发起操作后无需等待结果，可以继续处理其他任务**。当系统中存在大量网络请求、数据库访问或文件读写等 I/O 操作时，异步编程能够显著提高资源利用率和系统并发能力。

## 进程（Process）

在编写 Python 程序时，我们经常会看到这样的命令：

```bash
python main.py
```

当按下回车后，操作系统会加载 Python 解释器，并为当前程序分配运行所需的资源，例如内存空间、文件句柄以及系统资源等。此时，一个新的进程（Process）便被创建出来。

进程是一种抽象的概念，从来没有统一的标准定义看，一般由程序、数据集合和进程控制块三部分组成：

- 程序用于描述进程要完成的功能，是控制进程执行的指令集；
- 数据集合是程序在执行时所需要的数据和工作区；
- 程序控制块，包含进程的描述信息和控制信息，是进程存在的唯一标志。

进程是程序的一次运行实例，是操作系统进行资源分配和调度的基本单位。例如，我们电脑上同时运行着多个应用程序：`google`，`wechat`，`vscode`等等，从操作系统的角度来看，它们都是独立的进程，每个进程都拥有独立的内存空间和系统资源，彼此之间互不影响。

### 进程的作用

进程最大的作用是**实现资源隔离**，每个进程拥有独立的地址空间，不会导致某个程序崩溃引发系统崩溃。

### 进程与线程的关系

进程可以理解为一个运行环境，线程则是真正执行代码的执行单元，一个进程中可以包含一个或多个线程，**线程共享进程的内存和资源**，但各自拥有独立的执行栈和程序计数器，所以系统在产生一个线程，或是在各个线程之间作切换工作时，负担要比进程小得多，也正因为如此，线程也被称为轻量级进程。一个进程至少包含一个线程，这个线程通常称为主线程。

线程是操作系统调度的最小执行单位。当一个进程中存在多个线程时，操作系统会负责决定哪个线程获得 CPU 时间片，并在多个线程之间进行切换，这种切换方式称为**抢占式调度（Preemptive Scheduling）**。线程无法决定自己何时被切换，所有调度工作都由操作系统完成。

|     特性     | 进程                                 | 线程                                   |
| :----------: | ------------------------------------ | -------------------------------------- |
| **基本定义** | 操作系统资源分配的基本单位           | CPU 调度和执行的基本单位               |
| **内存空间** | 拥有独立的地址空间，进程间数据隔离   | 共享所属进程的地址空间                 |
| **系统开销** | 较大，创建或切换进程需要重新分配资源 | 较小，线程切换只需保存和设置少量寄存器 |
| **通信成本** | 较高，需借助 IPC（管道、消息队列等） | 极低，直接读写进程内存即可实现         |
|  **健壮性**  | 高，一个进程崩溃通常不影响其他进程   | 较低，一个线程崩溃可能导致整个进程崩溃 |

## 协程

在同步程序中，一个函数一旦开始执行，就会一直运行到结束后才会返回。在执行过程中，如果遇到网络请求、数据库查询或文件读写等 I/O 操作，程序往往需要等待这些操作完成后才能继续执行。

```python
import time 
def task(): 
    print("开始任务") 
    time.sleep(5) 
    print("任务结束")
```

为了提高资源利用率，提出了协程（Coroutine）的概念。协程是一种能够在**执行过程中主动让出控制权，并在未来恢复执行状态的函数**，当协程执行到某个需要等待的操作时，它可以主动暂停自己，将 CPU 的执行权交给其他任务；当等待的操作完成后，再从暂停的位置继续执行。与普通函数相比，协程最大的特点在于**可暂停**和**可恢复**。

在 Python 中，协程通常通过 `async` 和 `await` 关键字定义和使用：

```python
import asyncio 
async def task(): 
    print("开始执行") 
    await asyncio.sleep(3) 
    print("继续执行")
```

当程序执行到 `await` 时，当前协程会主动挂起，并将执行权交给事件循环（Event Loop）去调度其他协程运行。当等待的操作完成后，再从 `await` 之后的位置继续执行。因此可以将协程简单理解为是一种能够保存执行现场、主动暂停和恢复执行的轻量级任务，是 Python 异步编程的核心基础。 

### 事件循环

协程既然只是一个能够暂停和恢复执行的函数，那么究竟是谁负责让这些协程运行起来的？答案就是事件循环（Event Loop）。事件循环是整个 `asyncio` 异步编程模型的核心，它负责管理协程的生命周期、监听各种 I/O 事件，并在合适的时机恢复暂停的任务。如果说协程是一个个等待执行的工作任务，那么事件循环就是负责调度这些任务的管理者。协程本身并不会自动运行，当我们调用一个协程函数时，得到的只是一个协程对象，这个对象记录了需要执行的代码、当前执行位置以及相关状态信息，只有将其交给事件循环后，协程才会真正开始执行。

从本质上来看，事件循环是一个持续运行的调度器。它会不断检查当前是否存在可以执行的任务，然后让这些任务向前推进。当某个协程执行过程中遇到需要等待的操作时，例如网络请求、数据库查询、文件读写或者定时器等待，协程会通过 `await` 主动让出执行权，此时事件循环会暂停当前协程，并记录其恢复条件，然后转而执行其他可以运行的任务。当等待的事件完成之后，事件循环会收到通知，再将对应的协程恢复到暂停的位置继续执行。整个过程会持续不断地重复，因此被称为事件循环。

因此可以将事件循环理解为整个异步系统的大脑。协程定义了任务本身，`await` 提供了主动让出执行权的能力，而事件循环则负责监听外部事件、调度协程运行以及恢复暂停任务。没有事件循环，协程仅仅是一个尚未执行的对象；有了事件循环，协程才真正具备了高效并发执行的能力，这也是 Python 异步编程体系能够成立的基础。

### asyncio

`asyncio` 是 Python 标准库提供的异步编程框架，它为开发者提供了一套完整的异步编程模型。通过 `asyncio`，我们可以编写高并发的网络服务、爬虫系统、数据库应用以及 AI Agent 系统，而无需创建大量线程。

在同步编程中，当程序执行到网络请求、数据库查询或者文件读写等操作时，往往需要停下来等待结果返回。在等待期间，CPU 实际上处于空闲状态，无法处理其他任务。而 `asyncio` 的核心思想是，当一个任务进入等待状态时，主动让出执行权，由事件循环调度其他任务继续执行，从而充分利用等待时间，提高系统的整体吞吐量。一个典型的 `asyncio` 程序通常由协程、任务和事件循环三部分组成。协程使用 `async def` 定义，代表一个异步任务。

```python
async def hello():
    print("Hello World")
```

与普通函数不同，调用协程不会立即执行，而是返回的是一个协程对象，而不是执行结果。只有当协程被事件循环调度时，代码才会真正运行。在实际开发中，事件循环通常由 `asyncio.run()` 自动创建和管理。

```python
import asyncio

async def main():
    print("Hello asyncio")

asyncio.run(main())
```

当程序启动后，`asyncio` 会创建事件循环，将协程注册到事件循环中，并持续监听任务状态。当某个协程执行到 `await` 时，意味着当前任务需要等待某个异步操作完成，此时协程会主动挂起，并将执行权交还给事件循环。

```python
import asyncio 

async def task(): 
    print("开始执行") 
    await asyncio.sleep(3) 
    print("继续执行")
```

这里的 `await asyncio.sleep(3)` 并不会阻塞整个程序。相反，它会告诉事件循环当前任务需要等待 3 秒，在这期间你可以去执行其他任务。当等待时间结束后，事件循环会再次恢复该协程的执行。为了实现真正的并发执行，`asyncio` 提供了 Task 机制。Task 可以理解为被事件循环管理的协程对象。当一个协程被包装为 Task 后，事件循环就能够独立地调度它。在实际项目中，最常见的场景往往是同时执行多个异步任务。例如同时请求多个接口：

```python
results = await asyncio.gather( fetch_user(), fetch_order(), fetch_product() )
```

值得注意的是，`asyncio` 并不会让程序的计算速度变得更快。它解决的是等待的问题，而不是计算的问题。对于网络请求、数据库访问、文件读写等 I/O 密集型任务，`asyncio` 可以显著提高系统并发能力；但对于图像处理、机器学习训练、科学计算等 CPU 密集型任务，仍然应该优先考虑多进程方案。
