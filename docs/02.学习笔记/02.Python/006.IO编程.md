# Python 文件与 IO 到底该怎么写？从 open 到序列化一次讲清楚

文件读写大概是 Python 里「最容易被写慢、写错」的一块——语法本身不难，难的是那些没人提醒你的细节：编码、缓冲、指针、换行符。很多人直到遇到「乱码」「内存爆掉」「数据没落盘」才回头补课。这篇文章就是把这些细节一次讲透。

适合写过 Python、但读写文件一直「能用就行」，或者做数据处理、日志、爬虫这类高频碰文件的人。读完你能想明白三件事：**文件对象到底怎么读怎么写、指针和缓冲这些隐形机制是怎么回事、以及序列化和路径处理该怎么选**。

## 一、文件读写基础：open 与读写模式

### open 与模式

`open()` 是唯一的入口，第一个参数是路径，第二个是模式，`encoding` 指定编码。

```python
with open("demo.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n第二行\n")

with open("demo.txt", "r", encoding="utf-8") as f:
    print(repr(f.read()))   # '第一行\n第二行\n'
```

**模式速查表**：

| 模式 | 含义 |
|------|------|
| `r` | 只读（默认，文件必须存在） |
| `w` | 只写，**先清空**再写（文件不存在则创建） |
| `a` | 追加，写在文件末尾（不清空） |
| `x` | 独占创建，文件已存在则报错 |
| `b` | 二进制模式（`rb`/`wb`） |
| `+` | 读写（`r+`/`w+`/`a+`） |

**注意点**：`w` 会**清空原文件**，这是数据丢失的头号元凶。想保留原内容就追加用 `a`；想「文件不存在才创建、存在就报错」用 `x`。写代码前先想清楚「我到底要清空还是追加」。

### 文本 vs 二进制

加了 `b` 就是二进制模式，读写的是 `bytes`；不加就是文本模式，读写的是 `str`，自动帮你做编解码。

```python
# 二进制：写读的都是 bytes
with open("data.bin", "wb") as f:
    f.write(b"\x00\x01\x02")

with open("data.bin", "rb") as f:
    print(f.read())   # b'\x00\x01\x02'
```

**注意点**：文本模式必须指定 `encoding`，否则用系统默认编码，同一份代码在 Windows（默认 GBK）和 Linux（默认 UTF-8）上行为可能不一致，是乱码的常见来源。凡是写文本，养成 `encoding="utf-8"` 的习惯。

### with 与文件关闭

忘掉 `close()` 的文件，轻则占着句柄不释放，重则缓冲区的数据没落盘就丢。`with` 会保证文件在离开代码块时**一定被关闭**（哪怕中间抛异常），所以永远用 `with`：

```python
# 不推荐
f = open("demo.txt", "r", encoding="utf-8")
data = f.read()
f.close()   # 忘了这行就出问题

# 推荐
with open("demo.txt", "r", encoding="utf-8") as f:
    data = f.read()
# 到这里文件已经自动关闭了
```

## 二、高效读文件：read 家族与文件指针

### read / readline / readlines / for line

读文件有四种姿势，内存表现完全不同：

```python
# read()：一次读完整个文件，返回一个字符串
with open("demo.txt", "r", encoding="utf-8") as f:
    print(repr(f.read()))        # '第一行\n第二行\n'

# readline()：一次读一行
with open("demo.txt", "r", encoding="utf-8") as f:
    print(repr(f.readline()))    # '第一行\n'

# readlines()：一次读完所有行，返回 list
with open("demo.txt", "r", encoding="utf-8") as f:
    print(f.readlines())         # ['第一行\n', '第二行\n']

# for line in f：逐行迭代，最省内存
with open("demo.txt", "r", encoding="utf-8") as f:
    for line in f:
        print(repr(line))        # '第一行\n' / '第二行\n'
```

**误区一：`read()` 一次性读大文件，内存爆掉**。`read()` 和 `readlines()` 会把**整个文件**塞进内存。文件几百 MB、几个 GB 时，直接 OOM。正确处理是**逐行迭代**——`for line in f` 是惰性的，一次只读一行，内存占用恒定。

```python
# 处理大文件：逐行，永不把整个文件读进内存
with open("big.log", "r", encoding="utf-8") as f:
    for line in f:
        process(line)   # 一次只处理一行
```

### 文件指针 seek / tell

文件对象内部有个「指针」标记当前读写位置，`tell()` 看它在哪，`seek()` 移动它。**二进制模式下简单可预测**：

```python
with open("demo.txt", "rb") as f:
    f.seek(3)          # 跳到第 3 个字节
    print(f.tell())    # 3
    print(f.read(3))   # b'\xe7\xac\xac'
```

**CPython 细节①：文本模式的 `tell()` 返回的是字节偏移，不是字符数**。`第一行\n` 是 4 个字符，但 `tell()` 返回的是 10——因为「第一行」三个中文字符在 UTF-8 里各占 3 字节，加换行 1 字节，共 10 字节。

```python
with open("demo.txt", "r", encoding="utf-8") as f:
    f.readline()        # 读 '第一行\n'
    pos = f.tell()
    print(pos)          # 10  是字节数，不是字符数 4
```

**误区二：文本模式 `seek(1)` 落到多字节字符中间会报错**。

```python
with open("demo.txt", "r", encoding="utf-8") as f:
    f.seek(1)           # 落到 '第' 的第 2 个字节中间
    # f.read(1)         # UnicodeDecodeError: invalid start byte
```

因为文本模式 `seek()` 只能安全地跳到「字符边界」，随便给一个字节偏移，很可能卡在多字节字符的半截上。**正确姿势**：只用 `seek(0)` 回到开头，或者把 `tell()` 返回的位置原样传回 `seek()`：

```python
with open("demo.txt", "r", encoding="utf-8") as f:
    f.readline()
    pos = f.tell()      # 记住这个位置
    f.readline()
    f.seek(pos)         # 回到刚才的位置
    print(repr(f.readline()))   # '第二行\n'
```

记住一句话：**二进制随便 seek，文本只 seek 到 0 或 tell() 记下的位置**。

## 三、内存流与路径：StringIO/BytesIO 与 pathlib

### StringIO / BytesIO：内存里的「文件」

有时候你不想真的碰磁盘，只是想在内存里模拟一个文件（比如测试、或给一个「需要文件对象」的接口喂数据），就用 `io.StringIO` / `io.BytesIO`。

```python
import io

sio = io.StringIO()
sio.write("hello")
sio.seek(0)
print(sio.read())   # hello

bio = io.BytesIO()
bio.write(b"hi")
bio.seek(0)
print(bio.read())   # b'hi'
```

**注意点**：它和真实文件对象接口完全一致（`read`/`write`/`seek`/`with`），所以能让「写文件的代码」和「写内存的代码」共用一套逻辑，测试时特别好用。

### pathlib：现代路径处理

老代码用 `os.path` 一堆函数拼路径，现代 Python 用 `pathlib.Path`，把路径当成对象来操作，更清晰：

```python
from pathlib import Path

p = Path("/tmp/io_test/demo.txt")
print(p.name)       # demo.txt
print(p.suffix)     # .txt
print(p.parent)     # /tmp/io_test
print(p.exists())   # True
print(p.with_suffix(".bak"))   # /tmp/io_test/demo.bak

# 遍历目录
for f in Path(".").glob("*.txt"):
    print(f)
```

**注意点**：`pathlib` 是 Python 3.4+ 引入、3.6+ 基本替代 `os.path` 的推荐写法。新代码统一用 `Path`，别再手写字符串拼接（`"/".join(...)` 在 Windows 上就错了）。

### os 目录操作（简要）

`os` 模块负责文件系统层面的操作：

```python
import os

print(sorted(os.listdir(".")))   # ['data.bin', 'demo.txt', ...]
os.makedirs("sub/dir", exist_ok=True)   # 递归建目录
os.rename("demo.txt", "demo_old.txt")   # 重命名
os.remove("demo_old.txt")               # 删文件
```

## 四、序列化：json 与 pickle

### JSON

`json` 把 Python 的 dict/list 和 JSON 字符串互转，是跨语言、跨系统交换数据的标准格式。

```python
import json

data = {"name": "小明", "age": 18}

s = json.dumps(data)
print(s)                                   # {"name": "\u5c0f\u660e", "age": 18}
print(json.dumps(data, ensure_ascii=False))  # {"name": "小明", "age": 18}
print(json.loads(s) == data)               # True
```

**注意点**：`dumps`/`dump` 是「序列化」（对象 → 字符串），`loads`/`load` 是「反序列化」（字符串 → 对象）。默认 `ensure_ascii=True` 会把非 ASCII 字符转成 `\uXXXX`，想让人能看懂中文就传 `ensure_ascii=False`。

### pickle

`pickle` 能把**任意 Python 对象**（包括自定义类的实例）序列化成字节，存盘或传输，再原样还原。

```python
import pickle

class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __eq__(self, other):
        return (self.x, self.y) == (other.x, other.y)

p = Point(1, 2)
with open("p.pkl", "wb") as f:
    pickle.dump(p, f)
with open("p.pkl", "rb") as f:
    q = pickle.load(f)
print(q == p, q.x, q.y)   # True 1 2
```

**误区三：`pickle.load` 加载不可信数据等于执行任意代码**。pickle 反序列化的过程会**执行构造代码**，一个精心构造的 pickle 字节流可以让你 `import os` 然后 `os.system(...)`。所以：

- 永远**不要 `pickle.load` 来自网络、用户上传、不可信来源的数据**。
- 跨语言、跨系统交换数据，用 JSON，别用 pickle。
- pickle 只适合「自己程序内部存中间结果、且数据完全可信」的场景。

**对比表**：

| 特性 | json | pickle |
|------|------|--------|
| 数据格式 | 文本（字符串） | 二进制（bytes） |
| 支持类型 | dict/list/str/int/float/bool/None | 任意 Python 对象 |
| 跨语言 | ✅ 通用标准 | ❌ 仅 Python |
| 可读性 | ✅ 人能读 | ❌ 二进制 |
| 安全性 | ✅ 相对安全 | ❌ 反序列化有代码执行风险 |
| 用途 | 交换数据、API、配置 | 内部缓存、临时存对象 |


## 五、缓冲、编码与常见坑

### 缓冲与 flush

**CPython 细节②：文件对象默认全缓冲，底层是三层结构**。`io` 模块把文件对象分成三层：最底下是 `RawIOBase`（直接操作文件描述符），中间是 `BufferedIOBase`（内存缓冲区），最上面是 `TextIOBase`（文本编解码）。你调 `f.write("hello")` 时，数据其实只是被写进了**内存缓冲区**，还没到磁盘。

```python
f = open("log.txt", "w", encoding="utf-8")
f.write("这条日志")   # 现在还在内存里，磁盘上可能还没有
# ...
f.flush()            # 强制刷到磁盘
f.close()            # close 也会自动 flush
```

**什么时候要 `flush`**：写日志想看实时输出、多个进程盯着同一个文件、或者数据很关键怕断电丢失时，手动 `flush`。日常用 `with` 就够了，因为 `close()` 会自动刷盘。

### 换行符与编码的坑

Windows 和 Linux 的换行符不一样（`\r\n` vs `\n`）。Python 文本模式默认开启**通用换行**：读的时候自动把 `\r\n` 转成 `\n`，写的时候 `\n` 又转回系统默认。所以：

- 读写文本用文本模式，Python 帮你处理换行，跨平台省心。
- 读写二进制（图片、压缩包、协议数据）**必须**用 `b` 模式，否则换行符转换和编解码会把数据搞坏。

这也是「文本用 `r/w`，二进制用 `rb/wb`」这条分界线的由来。


## 小结

回头看这条主线：**open 与模式 → read 家族与指针 → 内存流与路径 → 序列化 → 缓冲与编码**。三句话收尾：

1. **读写文件永远用 `with`，文本必带 `encoding="utf-8"`**——这是消灭乱码和句柄泄漏的两个铁律。
2. **大文件用 `for line in f` 逐行读，别用 `read()` 一把梭**；文本模式 `seek` 只认 `0` 和 `tell()` 记下的位置。
3. **跨系统交换数据用 JSON，别用 pickle**——pickle 只能用于「自己人、可信数据」的内部缓存。

### 几个常见问题

**Q1：`w` 和 `a` 有什么区别？**
`w` 会**先清空**文件再写，`a` 是**追加**到末尾不清空。写之前想清楚是覆盖还是追加。

**Q2：什么时候用 `rb`/`wb`，什么时候用 `r`/`w`？**
读写真文本（日志、源码、配置文件）用文本模式；图片、压缩包、协议字节用二进制模式。二进制模式不会做编解码和换行转换。

**Q3：大文件怎么读不爆内存？**
用 `for line in f` 逐行迭代，或 `f.read(1024)` 分块读。别用 `read()`/`readlines()` 一次性全读。

**Q4：pickle 为什么危险？**
反序列化会执行构造代码，加载不可信数据可能导致任意代码执行。跨系统用 JSON，pickle 只用于可信的内部缓存。

**Q5：写了文件怎么磁盘上没变化？**
数据还在内存缓冲区，没 `flush` 也没 `close`。用 `with` 保证关闭，需要实时落盘就手动 `flush`。

### 本篇知识地图

| 知识点 | 一句话要点 | 关键结论 |
|--------|-----------|---------|
| open 与模式 | r/w/a/x/b/+ | w 会清空文件，追加用 a |
| 文本 vs 二进制 | str vs bytes | 文本必带 encoding |
| with | 自动关闭文件 | 永远用 with，别手写 close |
| read 家族 | read/readline/readlines/for | 大文件用 for line |
| seek / tell | 移动/查看指针 | 文本模式 seek 只认 0 和 tell() |
| StringIO / BytesIO | 内存里的文件 | 测试、模拟文件对象 |
| pathlib | 路径当对象 | 替代 os.path |
| json | 跨语言序列化 | ensure_ascii=False 显示中文 |
| pickle | 任意对象序列化 | 不可信数据别 load |
| 缓冲 | write 只进内存 | 实时落盘要 flush |
| 换行符 | 通用换行转换 | 二进制模式不转换 |
