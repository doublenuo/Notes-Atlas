# Python 第三方模块到底该怎么用？从 requests 到 numpy 一次讲清楚

Python 的强大很大程度来自它的**第三方生态**——标准库解决不了的，`pip install` 一下就有现成的。但「会用包」和「用好包」是两回事：环境怎么隔离、请求怎么加超时、依赖怎么锁版本，这些才是真实项目里的分水岭。这篇把最常用的几个第三方库和最佳实践一次讲清。

适合已经会写 Python、但「装包、发请求、处理数据」一直是凭感觉做的人。读完你能想明白三件事：**虚拟环境和依赖怎么管理、requests/numpy/pandas 这些库怎么用、以及怎么选包、怎么避免踩供应链的坑**。

## 一、包管理：pip、虚拟环境与依赖

### 虚拟环境：为什么要隔离

**CPython 细节①：venv 隔离依赖的原理**。`python -m venv` 会创建一个独立的目录，里面有自己的 `site-packages`（放第三方包的目录），并拷贝/链接一份 Python 解释器。在这个环境里 `pip install`，包装进的是**这个 venv 自己的目录**，不会污染系统 Python。

**误区一：全局装包污染环境**。直接 `pip install`（不建 venv）会把包装进系统 Python，多个项目互相冲突（项目 A 要 pandas 1.x、项目 B 要 2.x），升级一个包可能搞崩另一个项目。

```bash
python -m venv .venv          # 创建虚拟环境
source .venv/bin/activate     # 激活（Linux/macOS）
# .venv\Scripts\activate     # Windows
pip install requests          # 装进这个 venv，不污染全局
```

**注意点**：现代更推荐用 `uv`（001 篇提过）——它集成了 venv + pip，还更快、能锁版本。但「为什么要隔离」这个原理，用 `venv` 理解最直观。

### 依赖管理文件

把项目的依赖写进文件，别人才能复现你的环境：

```text
# requirements.txt
requests==2.31.0
numpy==2.0.0
```

用 `pip install -r requirements.txt` 一键装齐。更现代的方案是 `pyproject.toml`（声明依赖 + 项目元数据）。**关键是用 `==` 锁死版本**，别写 `requests`（不锁版本）。

## 二、requests：HTTP 请求的事实标准

### GET 与 POST

`requests` 是发 HTTP 请求最流行的库，API 友好到「看名字就懂」。底层用的是 `urllib3`（再往下就是上一篇文章讲的 socket）。

```python
import requests

r = requests.get("https://httpbin.org/get", params={"a": 1})
print(r.status_code)       # 200
print(r.json()["args"])    # {'a': '1'}   query 参数

r = requests.post("https://httpbin.org/post", json={"name": "小明"})
print(r.status_code)       # 200
print(r.json()["json"])    # {'name': '小明'}   JSON body
```

**注意点**：`r.json()` 把响应解析成 dict，`r.text` 是原始字符串，`r.content` 是 bytes。GET 用 `params` 传 query，POST 用 `json=` 传 JSON、`data=` 传表单。

### 超时与异常

**误区二：requests 不设超时、不处理异常**。默认 `requests.get(...)` **没有超时**，如果对方服务器挂起，你的程序会**永久卡住**。生产代码必须设 `timeout` 并捕获异常：

```python
try:
    r = requests.get("https://example.com", timeout=5)
    r.raise_for_status()    # 状态码不是 2xx 就抛异常
except requests.exceptions.Timeout:
    print("请求超时")
except requests.exceptions.RequestException as e:
    print("请求出错:", e)
```

**注意点**：`timeout=5` 表示「连接 + 读」总共最多 5 秒；`raise_for_status()` 把 4xx/5xx 转成异常，避免「接口返回 404 你却当成功处理」。这两行是写网络请求的标配。

## 三、numpy 与 pandas：数据科学基石

### numpy：向量化计算

`numpy` 的核心是 `ndarray`（N 维数组），最大的威力是**向量化**——对整个数组做运算，一次 C 循环搞定，比 Python 手写 for 循环快几个数量级。

```python
import numpy as np

a = np.array([1, 2, 3])
print(a * 2)          # [2 4 6]  整个数组同时乘，不用写循环
print(np.arange(5))   # [0 1 2 3 4]
print(a.sum())        # 6
print(a.mean())       # 2.0
```

**注意点**：`a * 2` 是对**每个元素**乘 2（广播），不是列表重复。`numpy` 数组和 Python 列表长得像但完全不同——数组要求**所有元素同类型**，运算按元素进行。这也是它为什么快。

### pandas：表格数据处理

`pandas` 的 `DataFrame` 是「带行列标签的表格」，专治 CSV、Excel、数据清洗、聚合统计。

```python
import pandas as pd

df = pd.DataFrame({"name": ["小明", "小红", "小刚"], "age": [18, 20, 22]})
print(df)
#   name  age
# 0   小明   18
# 1   小红   20
# 2   小刚   22

print(df["age"].mean())          # 20.0  平均年龄
print(df[df["age"] > 19])        # 筛选年龄 > 19 的行
#   name  age
# 1   小红   20
# 2   小刚   22
```

**注意点**：`df["age"]` 取一列，`df[df["age"] > 19]` 是**布尔筛选**——条件是「每行的 age 是否 > 19」，这是 pandas 最常用的写法。读文件用 `pd.read_csv("x.csv")`，写用 `df.to_csv("out.csv")`。

## 四、pydantic、httpx 与 matplotlib

### pydantic：数据校验

`pydantic` 用类型注解定义「数据模型」，自动做**类型校验和转换**，是 FastAPI 的底座，也常用于校验配置、接口数据。

```python
from pydantic import BaseModel

class User(BaseModel):
    name: str
    age: int

u = User(name="小明", age=18)
print(u.name, u.age)        # 小明 18
print(u.model_dump())       # {'name': '小明', 'age': 18}

# User(name="小明", age="十八")  # 校验失败，抛 ValidationError
```

**注意点**：pydantic v2 用 `model_dump()`（v1 的 `.dict()` 已废弃）。传错类型（比如 `age` 传字符串）会直接抛 `ValidationError`，把「脏数据」挡在入口。这是它和手写 `if isinstance(...)` 校验的本质区别——声明式、可复用。

### httpx：异步 HTTP

`httpx` 是「支持异步的 requests」——API 几乎一样，但能配合 `asyncio` 并发发请求。需要异步 HTTP 时用它（`aiohttp` 是另一个选择）。

```python
import httpx

# 同步用法和 requests 几乎一样
r = httpx.get("https://example.com")
print(r.status_code)

# 异步用法
# async with httpx.AsyncClient() as client:
#     r = await client.get("...")
```

### matplotlib

`matplotlib` 是画图的事实标准，`numpy`/`pandas` 的标配可视化工具：

```python
import matplotlib.pyplot as plt

plt.plot([1, 2, 3], [1, 4, 9])   # 画折线
plt.show()                        # 显示图形窗口
```

**注意点**：`plt.show()` 会弹窗口；在 Jupyter 里用 `%matplotlib inline` 让图内嵌显示。

## 五、选包与最佳实践

### 怎么选一个靠谱的包

PyPI 上有几十万个包，质量参差不齐。选包前看几个指标：

- **维护状态**：最近更新时间、commit 频率（几年没更新的包，大概率有 bug 没人修、或有安全漏洞）。
- **使用量**：GitHub stars、下载量——用的人多，坑基本都被踩过、有答案了。
- **文档质量**：文档清不清楚、有没有示例。
- **依赖**：依赖链干不干净、体积大不大。

**误区三：不锁依赖版本**。项目今天能跑，不代表三个月后 `pip install` 还能跑——某个包发了破坏性更新，你的项目就崩了。锁版本是基本素养：

```text
# 用 == 锁死
requests==2.31.0
numpy==2.0.0

# 更彻底：pip freeze 导出当前环境的精确版本
pip freeze > requirements.txt
```

### 对比表

**requests vs urllib vs httpx**：

| 库 | 定位 | 特点 |
|----|------|------|
| `urllib` | 标准库 | 无需安装，但 API 繁琐、易错 |
| `requests` | 同步 HTTP | API 最友好，事实标准 |
| `httpx` | 同步+异步 | API 类似 requests，支持异步 |

**包管理工具**：

| 工具 | 特点 |
|------|------|
| `pip` | 标准装包工具 |
| `venv` | 内置虚拟环境 |
| `uv` | 新一代，快，集 venv+pip+锁版本 |
| `conda` | 跨语言，管理 Python 版本 + 包 |

**注意点**：安全是选包时最容易被忽略的一环——恶意包、被投毒的包是真实存在的。装包前看一眼包的来源、别装「名字像但下载量极低」的可疑包，重要项目用 `pip-audit` 这类工具扫依赖漏洞。


## 小结

回头看这条主线：**虚拟环境与依赖 → requests → numpy/pandas → pydantic/httpx/matplotlib → 选包**。三句话收尾：

1. **建项目先建 venv、锁依赖版本**——这是隔离冲突和保证可复现的两条铁律。
2. **requests 必设 `timeout` 并捕获异常**，`raise_for_status()` 把错误状态码转成异常。
3. **numpy 向量化、pandas 用 DataFrame、pydantic 做校验**——数据处理和校验都别手写循环。

### 几个常见问题

**Q1：为什么不直接用系统 Python 装包？**
多个项目会互相冲突，升级一个包可能搞崩别的项目。每个项目一个 venv，隔离干净。

**Q2：`requirements.txt` 里要不要锁版本？**
要。用 `==` 锁死，或 `pip freeze` 导出精确版本。不锁版本，将来 `pip install` 装上破坏性新版本，项目就崩。

**Q3：requests 为什么请求会卡住不动？**
大概率没设 `timeout`。requests 默认不超时，对方服务器挂起就永远等。加 `timeout=5`。

**Q4：numpy 数组和 Python 列表有什么区别？**
数组要求所有元素同类型，运算是**按元素**进行的（`a*2` 是每个元素乘 2），且由 C 实现、快得多。列表是「对象引用」的集合。

**Q5：怎么选一个靠谱的第三方包？**
看维护状态（更新时间）、使用量（stars/下载）、文档质量、依赖链。别装可疑的低下载量包，重要项目扫依赖漏洞。
